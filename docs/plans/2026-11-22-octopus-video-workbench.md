# octopus_DSH video workbench integration plan

English | [中文](2026-11-22-octopus-video-workbench.zh.md)

**Status**　Second review draft. The four release decisions are incorporated. Phase 0 awaits approval. Phases 1 and 2 require their respective qualification evidence.

## User flow

Open Video Production from the home capability menu or start in a standard conversation. Import photos, clips, real screenshots, narration, music, or SRT. The agent proposes shot order, timing, and source assets. Users can preview, export MP4, and resume editing after restarting the app. The works list retains the current revision, export progress, and prior successful exports. Qualify the basic tier with a 30–45 second nonprofit event recap. Qualify the advanced tier with a demo that uses real product screenshots to exercise Shotcraft shots and a template.

Phase 1 implementation requires the clean-environment basic local workflow and access checks, plus license evidence for that phase's assets and distribution method. Each optional generation route qualifies independently. Import and local editing remain available when a route fails. Phase 2 also requires advanced rendering, preview, and license evidence. Phase 0 uses the existing installed product and minimal test projects. It can begin with unpaid checks and synthetic assets. Qualify new workbench behavior end to end in phases 1 and 2.

## Project storage, revisions, and preview

Adopt MoneyPrinterTurbo's immutable revisions, stable shot IDs, and artifact reuse based on dependency fingerprints and verified SHA-256. Use the project design with DSH's jobs and media runtime. Projects record asset IDs, tracks, timing, input digests, template and renderer versions, settings, and exports. Reordering preserves shot IDs. Recompute footage, narration, captions, assembly, and mixing by dependency. Global caption style changes invalidate outputs that use that style. [MoneyPrinterTurbo project mode](https://github.com/harry0703/MoneyPrinterTurbo/blob/86e45a2233a72c41d83389ac5cb49bbf5f6a847d/docs/video-projects.md)

The [desktop-media](../../packages/experimental/desktop-media/README.md) Host owns versioned JSON, revisions, and shot dependencies under `$DSH_HOME/media/projects/`. Persist verified assets and immutable revisions before advancing the project pointer. Serialize writes per project, require an expected revision, and replace the pointer atomically. Repeated exports of the same revision share an in-progress job or committed output. The pointer and works catalogue are separate files. Serialize catalogue writes across projects and reconcile the index idempotently from committed export records on startup. Only a successful export for the still-current revision can advance the default output. Failures, cancellations, and late older jobs preserve the last successful output and export history.

Keep the project graph outside SessionEventMap. When a new session-link event is necessary, store only a skippable reference and mark that event `ignorable: true`. Model-visible tool results must be reconstructable from the session log. The workbench toggle disables the project editing entry. Existing media capabilities continue to provide session reading, the works catalogue, and native file opening. Test that prior exports can still be found and played with the workbench disabled and replay a log with a reader that lacks any new event types. Review persistence changes through the repository workflow. [Persistence type changes](../cookbook/reviewing-persistence-type-changes.md)

The required phase 1 preview uses the existing works entry. The Host resolves the work ID and opens the system player. For phase 2, qualify authenticated in-app preview over the desktop Host/Carrier route first. Preserve Tauri CSP, authorize session and artifact access against the project workspace. When resuming in a new session, verify access to the same workspace, and verify playback and seeking. Keep native file preview if embedding fails. Features that require interactive template preview qualify only after a working interactive route passes. If a local interactive template needs an external browser, phase 0 separately verifies loopback-only binding, time-limited project-scoped access, cleanup, and file access restrictions. Retain Shotcraft's asset import semantics. The fixed-port development server and unauthenticated iframes stay outside the product path. [Native media open](../../packages/experimental/desktop-media/src/local-open.ts) · [Desktop CSP](../../apps/desktop/src-tauri/tauri.conf.json)

## Shotcraft and paid generation

Preserve real screenshots, card-to-demo mapping, deterministic motion, and frame and video review. Prefer user assets, approved screenshots, and programmatic graphics. Keep always-mounted tool definitions small and return IDs, following the existing media tools. Load only needed cards and templates via skill tools or scoped file reads when users choose Shot Recipes. The standard session system prompt excludes the Shotcraft catalogue. Defer social sharing, Jianying export, automatic captioning, and beat analysis.

The Host enforces provider allowlists and paid admission for autonomous creation, templates, fallback, and worker calls. Use qualified MiniMax for stills and qualified MiniMax or explicitly selected Seedance 2.0 for video. The desktop exposes the Ark base URL and model or endpoint ID, with Beijing as the default address. The Host holds separate Ark and MiniMax keys. Check HTTPS destinations and redirects before sending credentials, and send them only to trusted Ark addresses confirmed by the user. Approval binds the provider route, assets, parameters, and cost ceiling. Route changes and new paid items require fresh approval. Templates cannot invoke GPT image generation or bypass the Host. [MiniMax text-to-image](https://platform.minimax.cn/docs/api-reference/image-generation-t2i) · [Seedance 2.0](https://docs.volcengine.com/docs/ark/seedance-2-0?lang=zh)

Check fingerprints and local file integrity before listing new generation items. Reused shots or narration add zero calls and ¥0. Keep the existing session defaults of eight paid calls and ¥40. Use the same atomic per-session budget check and reservation for existing media entry points and the workbench. Revalidate the current revision and confirmed route before dispatch. Release superseded reservations that have yet to dispatch. Estimate using the confirmed model, billing unit, and quantity, with one image per request in v1. Deduplicate requests and recover reservations after restart. Submitted or ambiguous requests continue to occupy budget while the Host reconciles their status where possible. Forbid automatic resubmission while the original charge remains unresolved. When resuming a project in another session, show the new session's budget and the project's prior spend. [Existing media budget](../../packages/experimental/desktop-media/README.md)

Download results immediately to a temporary file on the media store filesystem. Validate size, media format, and SHA-256. Move the file atomically before committing a shot version. Compare a provider checksum when supplied. Otherwise record the local digest and verify it again before reuse. Test interrupted and partial downloads, expiry, and local digest mismatches. On expiry, look for a recoverable result and retain prior versions. A new generation requires fresh approval.

Install the lightweight skill and index through the [desktop skill manifest](../../scripts/desktop-bundled-skills.json) and the workbench through the [desktop plugin manifest](../../scripts/desktop-profile-plugins.json). Pin the Shotcraft commit, shot cards, asset inventory, and checksums. Install reviewed templates and advanced components on demand. The worker runs independently of developer-global skills, preinstalled dependencies, and caches. [Shotcraft source](https://github.com/Vincentwei1021/video-shotcraft)

## Phase 0 qualification matrix

| Check | Required evidence and failure handling |
| --- | --- |
| Installation and runtime | Open a signed installer from Finder on a clean macOS arm64 account. Verify first launch and clear dependency guidance without Homebrew, system Node or Python, global skills, an additional browser, or caches. After installing user-side FFmpeg, exercise offline import, export, cancellation, and restart with a minimal project. Use the existing media capability to verify upgrade, disablement, and recovery paths. Record sources, versions, checksums, installer size change, downloads, and disk use. |
| Basic export | Use the user-installed FFmpeg and ffprobe to verify `h264_videotoolbox`/AAC, both aspect orientations, and paths containing Chinese characters and spaces. Burn subtitles with libass through `subtitles`/`ass` and inspect Chinese glyphs and punctuation using system PingFang or licensed Noto CJK. When filters or fonts are missing, verify available MP4 and separate SRT. Check fixed-gain narration and music mixing. If ducking or loudness normalization enters v1, exercise `sidechaincompress`/`loudnorm` and listen to the result. |
| Preview and advanced rendering | Verify native opening from the installed desktop, then test project authorization and denial of cross-project access with a minimal advanced preview. For pinned local Node, Remotion, Chrome or Chromium, fonts, and encoders, verify download sources, checksums, proxy behavior, and failure recovery. Render a still and a video from the actual template. Record timing, resource use, offline behavior, and preview-export parity. |
| Licensing and assets | Record licenses, notices, and actual redistribution separately for MoneyPrinterTurbo (MIT), Shotcraft code (Apache-2.0), demos, fonts, audio, and brand art. Obtain a written determination for the pinned Remotion version covering on-demand installation and product invocation, any Company License requirement, the license holder, and terms that institutions must accept. Withhold the advanced tier until the evidence and conditions are in place. |
| Domestic MiniMax | Use a single domestic pay-as-you-go key on `api.minimax.cn` to verify Image-01, `speech-2.8-hd`, and MiniMax-H3-Max. Public docs list Image-01 at ¥0.025 per image with a 24-hour URL lifetime. Verify actual entitlements, sizes and durations, billable image counts, bill entries, and downloads with the target account. Enable only qualified routes if Image-01 fails. |
| Seedance 2.0 | Use a mainland China network and an enabled Ark account to exercise the configurable route. Record the model or endpoint ID, region, quota, uploads, submission and polling, cancellation, restart recovery, and actual cost. Record task ID and download URL lifetimes separately. Qualify 2.0 only. |
| Failure and billing | Use an approved test budget and nonsensitive samples. Record successful calls and bills. Exercise throttling, billing denial, unknown submission, concurrent budget exhaustion, cancellation, expiry, checksum failure, low disk space, and network loss. Record user feedback, recovery actions, retained outputs, and charges. |

Phase 0 records include the date, build and dependency versions, environment, reproducible steps, redacted evidence, and conclusion. Phases 1 and 2 require Host behavior tests, session replay, and the normal installed entry. Verify playback and listening quality, reopened projects, missing assets, concurrent exports, late jobs, revisions in a new session, and continued access to prior exports after disabling the workbench.
