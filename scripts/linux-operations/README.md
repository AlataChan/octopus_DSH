# Linux operations tools

English | [中文](README.zh.md)

## Summary

These optional server-side tools connect the sandboxed DSH Agent to a finite Unix-socket operations broker and the existing Gamma WeChat desktop worker. They do not enter desktop boot composition or a DMG. The administrator installs them separately on the Linux host; the model receives no sudo or general Podman access.

## Commands and permissions

Use `host_status`, `service_status`, `service_logs`, `wechat_status` and `wechat_screenshot` for inspection. Service aliases, container restart targets and registered WeChat friends are administrator-configured. A worker `ready` heartbeat is a UI observation, not proof of network delivery.

For WeChat, `wechat_send` handles friends, `wechat_send_group` handles enrolled groups, `wechat_probe_group` runs read-only group identity probes under the shared account lock without entering text, and `wechat_publish_moment` handles ad hoc Moments when explicitly enabled. Authentication identifies who is speaking; broker authorization also verifies what the current Feishu message asks to send. A request qualifies for single-turn `direct=true` execution only when the full trusted ingress message unambiguously matches a direct send or publish form specifying the exact target, verbatim body text, and audience visibility (explicit `仅自己可见`/`私密` or `好友可见`/`公开`, or omitted only when an explicit configured default visibility is frozen in `prepare`), with no draft-only, negated, quoted, hypothetical, question or status framing. Draft-only instructions, conversational paraphrases, body substitutions, visibility escalations and older `direct=true` database rows never execute directly: `prepare` either refuses invalid parameters or returns a frozen `direct=false` preview that requires a subsequent authenticated `确认执行 <id>` reply from the owner, while duplicate or variant direct claims within one owner request are suppressed and two separate owner requests (even with identical text) receive independent 24-hex IDs and `{job_id}.{text_sha256[:12]}.png` evidence. Friends and groups are registered behind stable opaque IDs, unique aliases and unambiguous exact display or group names; ambiguous names, unbound or disabled targets, unknown recipients, friend-vs-group mismatches and target substitution fail closed. Ad hoc Moments keep an independent administrator toggle that defaults to disabled in production, enforce 220-non-whitespace-character, 4-line, reserved-string and 620x800 viewport rules without mutating text, and remain isolated from daily Moments deduplication and caps. Legacy single-recipient configuration and pre-upgrade queued jobs remain bound only to their original contact. Service and limits changes retain numbered confirmation, except exact structured restart commands. All operations retain duplicate suppression and uncertain-result reconciliation.

`set_limits` changes only logLines and previewSeconds; it saves a durable backup. `restore_limits` restores a completed change after a fresh confirmation and rejects a stale configuration preview. Arbitrary commands, paths, recipient IDs, group IDs, credential edits and target-allowlist changes are not exposed.

A WeChat job is queued until a worker receipt is available. `sent_verified` and `published_verified` mean the sender UI and complete body were checked; neither proves remote delivery, network visibility or recipient reading. `wechat_probe_group` returns `identity_verified` when the enrolled group detail surface, 1–2 member image anchors and exact group name match read-only. Uncertain execution becomes needs_review and is never automatically resent. The wrapper retains the original daily tick, daemon lock and account lock, passes ad hoc jobs to Gamma's `delivery.run_one` without a second outer flock, and uses an independent ad-hoc outbox and receipt namespace.

## Install and test

Install the isolated, lockfile-pinned MCP adapter dependencies with `npm ci --prefix scripts/linux-operations --ignore-scripts --no-audit --no-fund`. Run the Node suite with `pnpm run test:linux-operations` and the isolated release/installer checks with `python3 -m unittest scripts/linux-operations/tests/test_install_release.py -v`. The worker Python suite requires the actual Gamma source on PYTHONPATH and runs with `python3 -m unittest discover -s scripts/linux-operations/tests -p 'test_*.py' -v`; only the desktop is faked, not the existing queue transaction.

`install.py` is an administrator-only installer for the existing Octopus/Gamma host layout and preserves Python 3.6.8+ stdlib/syntax compatibility for bare host execution alongside Python 3.12+ container workers (`wechat_worker.py`). Supply `--source`, `--runtime` and `--node` as explicit absolute paths, optionally `--contacts-config` for a friend and enrolled-group registry, optionally `--adhoc-moments-config` to configure ad hoc Moments (disabled by default), and optionally `--autoreply-config` for explicit opt-in DSH auto-reply policy (strictly default-off). `RELEASE_FILES` packages all runtime broker, inbox projection, and isolated DSH auto-reply modules (`broker.mjs`, `operations.mjs`, `policy.mjs`, `mcp-server.mjs`, `readiness.mjs`, `wechat-inbox.mjs`, `wechat-autoreply.mjs`, `wechat-autoreply-dsh.mjs`, `wechat_worker.py`, `install.py`). In Phase A before stopping active services or switching symlinks, `install.py` rejects non-bootable test-only `transport.mode: 'adapter'` configs (both fresh and persisted in an existing `operations.json`), enforces dedicated non-empty credential provisioning for `deepseek-api-key` via a canonical root-owned `0600`/`0400` `environmentFile` (without group/world-writable ancestors, untrusted non-root symlinks, `-` prefixes, globs, or `%` systemd specifiers, while still allowing root-owned distro symlinks such as `/var/run -> /run`) or a validated existing `octopus-operations.service` / `.d/*.conf` `EnvironmentFile=` rather than caller login-shell variables, stages `RELEASE_FILES` into an isolated temporary symlinked release directory to verify local imports, policy validation, Gamma adapters (when enabled), Feishu `ownerNotices` capability (when enabled), DSH `resolveDshInstallAnchor`/`loadDshRuntimeModules`, and—when auto-reply is enabled—authentic staged `current/broker.mjs` Unix-socket startup in an isolated service environment built solely from those validated `EnvironmentFile` entries with zero external model calls. Optional `--autoreply-config` rejects embedded secret fields or unapproved `DEEPSEEK_API_KEY` fallbacks and wires only the validated canonical `environmentFile` path into `octopus-operations.service` `EnvironmentFile=`. The installer writes the DSH contact registry to a separate root-owned `config/octopus-contacts.json` sidecar next to Gamma's `config/config.json` so Gamma keeps ownership of its file, live account binding and daily flags while preserving original Gamma source and configuration backups. It replaces the worker entry with a wrapper that rechecks contact identity, ad hoc Moments limits and non-symlinked anchor bindings immediately before UI preflight and submission; the WeChat login container is not restarted. The ingress refresh waits for active human tasks to finish.

Credentials remain in the existing root-only environment files and are not copied into these tools. The broker socket directory is root-owned, its group is the dedicated Agent group, and the journal is root-private. Common credential assignments and bearer strings are redacted from bounded logs; administrators must still avoid logging secrets.

The friend-card OCR fallback requires an administrator-verified root-owned `config/octopus-friend-label.png` on the existing WeChat exchange; each bound direct friend requires root-owned non-symlinked search, sidebar and card anchors, and each bound group requires `own_chat_anchor`, a unique `group_anchor`, 1–2 distinct `group_member_anchors`, and native clipboard or `group_name_anchor` name verification without friend-card fallback injection. Installation rejects missing, duplicate, symlinked or writable anchors.

## WeChat-to-Feishu notifications and v1 producer contract

`wechat-inbox.mjs` (`WechatExchangeProjector` inside `broker.mjs`) and `@deepseek-ai/dsh-experimental-im-feishu` (`OwnerNoticeStorage`, `OwnerNoticeDispatcher` and `OwnerNoticeHandoffService` inside `ingress-plugin.ts`) form a two-stage, opt-in and default-off (`wechatNotifications.enabled: false` and `ownerNotices.enabled: false`) notification pipeline. The root-owned broker reads `wechatRoot` under pinned producer UIDs using `O_RDONLY | O_NOFOLLOW` and `fstatSync(fd)` checks, verifies every `adhoc/receipts/*.json` against `adhoc/outbox/*.json` and the frozen operation record in `operations.sqlite`, maintains private coalescing state in `wechat-inbox.sqlite`, and writes only minimal sanitized envelopes to a restricted `root:octopus-ingress` (`0750`/`0640`) handoff directory without loosening existing worker permissions (`wechatRoot` `0750`, `adhoc/outbox` `2750`, `adhoc/receipts` `0700`/`0600`) or giving `octopus-ingress` group `1000` or raw path access.

When `ownerNotices.enabled` is true alongside an active Feishu channel, `ingress-plugin.ts` opens a private `owner-notices.sqlite` (`im_owner_notice_notices` and `im_owner_notice_threads`) under its `ImWriterLease`, moves any `in_flight` record to `unknown` on startup, runs an independent non-overlapping `noticePump` decoupled from ordinary IM reply dispatch (`maxIngestPerCycle` defaulting to `20`, `maxSendsPerCycle` defaulting to `5`) using the shared `FeishuTransport.sendTextMessage` surface and live non-revoked `u_im_ingress_operators` binding, stops claiming new notices once shutdown begins while waiting within `shutdownTimeoutMs` for any active HTTP send to settle, tags content strictly `untrusted: true` with `authority: 'notice_only'`, and keeps `u_im_ingress_deliveries` untouched; disabling Feishu or revoking the operator fails closed with zero notifications sent.

On the broker half when `wechatNotifications.enabled` is true, inbound alerts use a reviewed 20-second sliding aggregation window per conversation (configurable 15–30 seconds, bounded by `inboundMaxBatchWaitSeconds` and `inboundMaxEventsPerBatch`, flushing `needs_human` / `needs_review` alerts immediately), assign one `wn_<12hex>` `noticeId` per batch, reuse the conversation thread's `replyMessageId`, keep bounded per-conversation context (`maxContextMessages`, `retentionDays`), emit asynchronous terminal receipt notices only for `sent_verified`, `published_verified`, `identity_verified`, `needs_review`, `failed_before_submit`, `refused`, `expired` and `auth_required` with non-delivery disclaimers, persist `'pending' -> 'written'` handoff state in `projected_notices` so failed or crash-interrupted handoff file writes recover deterministically on subsequent ticks or restarts without duplicating notices or replaying healthy/'unknown' deliveries, and include `wechat-inbox.mjs` plus optional `--notifications-config` and offline built `--feishu-package` support in `install.py`. Manual notice-reply (`wechat_reply_notice` via `wechatNotifications.manualReplyEnabled`, independently default-off and bounded by `manualReplyMaxAgeSeconds`, default `3600`) accepts only `{noticeId, text}` with no free-form target field, resolves `wn_<12hex>` read-only from the broker's `wechat-inbox.sqlite` ledger (`inbound_alert` friend or group origin with explicit observation-time producer `binding_sha256` and frozen intake binding, failing closed on pre-extension/inferred rows, missing/`null`/mismatched producer `binding_sha256`, outbound receipts, Moments alerts, review-only/unknown origins, or rebound/disabled contacts), enforces intact owner prompt matching (`回复 wn_<12hex>：<正文>`) for same-turn direct execution, clamps frozen and outbox deadlines to the earlier of operation TTL and current notice/lease lifetime (`source_observed_at` and `created_at`) without ever extending frozen deadlines, propagates `origin_notice_id` plus `origin_notice_key`, `origin_notice_observed_at`, and `origin_notice_created_at`, and treats `config/octopus-manual-reply.json` (`0o640`, root-owned) as the single authoritative runtime pause/lease state: broker boot (`startBroker`), projection ticks (`createBrokerProjectionLoop`), and ordinary `install.py` reinstalls apply tighten-only policy ceilings (`reconcileManualReplyConfigView`: never synthesizing missing or unreadable files, and never clearing `paused`, finite `lease_expires_at`, or reduced `max_age_seconds`, while failing closed on policy disable or account rebind). Operators pause or resume/lease manual replies explicitly as root without touching worker/ingress permissions via `node <current>/broker.mjs <policyPath> manual-reply <status|pause|resume> [--lease-seconds N] [--max-age-seconds N]` (taking immediate effect even on queued outbox jobs before worker UI preflight/submit) or `install.py --resume-manual-reply` / `--pause-manual-reply` (`--manual-reply-lease-seconds N`). When notifications are enabled (new or preserved), `install.py` Phase A resolves `@deepseek-ai/dsh-experimental-im-feishu/ingress` using the same precedence as `@deepseek-ai/dsh-app-boot` (`profile/package.json` + `profile/node_modules` local overrides before runtime installation BFS and profile fallback), refuses `.ts` sources or older packages lacking the exported `ownerNoticesCapability` and schema acceptance before stopping services, stages any verified `--feishu-package` build under `release_root/feishu-packages/<digest>` and materializes it inside `profile/node_modules` with profile dependency pinning, and rolls back `profile/package.json`, `node_modules`, `cordis.patch.yml` and `config/octopus-manual-reply.json` if ingress restart fails.

The local producer writes each inbound worker event to `wechatRoot/inbox/events/<event_id>.json` as a regular, non-symlinked, non-group/world-writable, non-world-accessible (`0600`/`0640`, max 32 KiB, pinned `inboundProducerUid` matching `adhoc/receipts` UID `1000`) JSON object matching Wire Schema v1. Required fields are `schema_version` (`1`), `event_id` (matching filename stem), `account_sha256` (64-hex SHA-256 of bound `account_id`), `trigger_type` (`friend_message` | `group_message` | `moments_interaction` | `needs_human`), `conversation_kind` (`friend` | `group` | `moments`), `conversation_ref` (bound `contact.id` for friends/groups, safe ref for Moments), `sender_name`, `source_ref`, `source_time` (`"unknown"` when unavailable), `observed_at` (epoch ms within retention and clock-skew bounds), non-empty `text` (`<= 4096` UTF-8 bytes), and contained verified `evidence_path` + `evidence_sha256` (`null` allowed only together on `needs_human`); optional fields are `conversation_name`, `sender_ref`, `quoted_sender`, `quoted_text`, `needs_review`, `reason` and `binding_sha256` (explicit 64-hex observation-time target binding digest matching the bound friend/group target; omitting `binding_sha256` or setting `null` projects strictly as a read-only `inbound_alert` with `reply_eligible = 0`, whereas any mismatched non-null digest is rejected fail-closed at ingestion).

Use `--inbound-scan-config` with a trusted administrator JSON file to enable desktop inbound scanning. The installer places the configuration beside the contact registry as `octopus-inbound-scan.json`. Set `enabled` explicitly and enroll each target. Use `self_mention_names` and per-group `group_inbound` metadata for group author and mention anchors. Use `registered_own_posts` for owned, verified publications. The worker reads one target under the shared account lock and records the cursor through durable inbound events.

An authenticated Feishu owner can request `看刚发的朋友圈评论` or `看<registered target>最近消息`. The lookup returns up to eight recorded observations from the bound conversation or the most recently observed owned post.

## Auto-reply policy and delivery

Automatic reply is disabled by default. Enable it with `--autoreply-config`, configure the dedicated transport, and choose a mode for each enrolled conversation. `draft_only` projects a draft to the owner when `projectOwnerNotices` is enabled. `unattended` also requires native sender proof and a fresh matching conversation tail. Group @ mentions require positive native corroboration and group quotes require a verified original message. An @all event is notice-only. The cooldown is applied per group.

The restricted DSH profile generates an answer or a request for human review. The broker freezes one decision and one destination in the journal. The desktop worker checks the short-lived root-owned permit, rechecks the original conversation while holding the account lock, and stops if the account already replied or the other side sent a newer message. Uncertain submissions stay in the journal for reconciliation. Feishu automatic-reply receipts pair the observed inbound message with the proposed reply and the sender-side terminal status.

Check native sender and tail behavior, clock and phone synchronization, installed credentials, and real Feishu delivery in the target account before enabling unattended mode. The Linux Moments adapter reads and routes comment activity. Its targeted comment reply still requires a verified native attachment control.

## Recovery and acceptance

Stop ingress before removing tools from its profile. Restore the saved profile and remove the worker systemd drop-in to return to the original worker. Restart the worker, broker and ingress only after checking active deliveries; preserve uncertain receipts for reconciliation. Never clear a receipt to force a retry.

Local fake-desktop tests do not establish real WeChat sending. Production acceptance separately verifies root/group permissions, installed MCP negotiation, real-model read-only tool calls, account/contact identity preflight and a human-authorized real message. No production recipient receives an automated test message merely because installation succeeded.
